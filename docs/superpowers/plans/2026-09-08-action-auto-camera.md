# Action-driven Auto Camera — Plan and Implementation

**Goal:** 무리를 계속 따라가면서 실제 액션에 따라 가까워지는 오토카메라.
**Status:** 사용자 승인으로 구현. 커밋·푸시 요청 포함. 2026-09-08 추가 피드백에 따라 특성 슬롯의 고정 탑뷰를 제거했다.
**Stack:** TypeScript, Three.js, Rapier, Vitest. 새 의존성 없음.

## 최종 동작

| 상황 | 카메라 | 종료 조건 |
| --- | --- | --- |
| 평소 | 가장 조밀한 live 무리의 실제 경로 위치를 계속 추적 | 유효한 액션 발생 |
| pinwheel/bumper 진입 | 무리를 계속 뒤에서 따라가며 더 가까이 접근. 슬롯 중앙 고정·탑뷰 전환 없음 | 군집 절반 통과 시 기본 거리, 80% 또는 빈 구간에서 액션 해제 |
| BOOST 성공 | 현재 군집을 유지하면서 가까운 추적 | 발동 당시 군집의 80%가 구간 출구 통과 또는 종료 |
| RUSH 진입 | 현재 후미 구슬을 추적 | 대상이 현재 구간을 통과하거나 finish/DNF |
| 막판 | live 수 ≤ max(3, ceil(originalCount × 0.1))부터 남은 구슬 추적 | 대상 종료 시 다음 live 후미; 전원 종료 시 마지막 구도 유지 |
| 코너 | 통과 인원 할당량 없이 현재 무리 위치를 따라 진행 | 실제 경로에 따라 다음 구간으로 이동 |

- 자동 카메라에서 특정 슬롯을 위에서 고정해 보여주는 코드는 제거했다. Bird View 버튼과 reduced-motion 전경 모드는 보존한다.
- 코너 진입 전 80% 통과를 기다리는 기존 군집 카메라의 위치 제한을 제거했다. 장애물 클로즈업 종료의 80% 조건과는 다른 정책이다.
- 카메라의 시선도 접선 연장선이 아닌 실제 경로상의 앞쪽 보간 지점을 바라본다. 커브 밖을 조준하거나 구간 경계에 정지하지 않는다.
- 8초/4초 주기 교대 및 이전 순위 진행률 선택기는 제거했다.
- 시간은 feature 클로즈업의 최소 1.8초 유지와 기존 수동 조작 후 3초 유예에만 사용한다. 무리가 실제로 슬롯 안으로 진행해야 클로즈업된다.

## 선택 규칙

1. 사용자 조작/Bird/reduced motion/pause가 자동 연출보다 우선한다.
2. 막판 > 현재 점유 장애물 > RUSH 진입 > BOOST > 일반 추적.
3. 같은 우선순위의 유효한 대상을 유지하고, 대상 소멸·빈 구간은 즉시 해제한다.
4. 신호를 큐에 쌓지 않는다. 수동 조작 중 발생한 과거 BOOST/RUSH를 나중에 재생하지 않는다.
5. 구간 통과는 진입 때 고정한 구슬 id 집합으로 센다. 역주행·DNF는 중복 집계하지 않는다.
6. 같은 장애물은 run당 한 번, 재시작 시 초기화. 지나친 구간을 뒤늦게 찾아가지 않는다.

### 브라우저 확인과 범위

100개 세로 레이스에서 BOOST, RUSH, pause/Bird/resume 및 마지막 구슬 추적을 확인했다. 300개 레이스는 OUT 없이 정상 결과 화면까지 완료했고 브라우저 error log는 비어 있었다. 슬롯 탑뷰 제거 후 300개 레이스를 다시 시작해 경로를 따라 움직이는 카메라와 커브 추적을 확인했다.

뷰포트는 360×800, 1024×768을 사용했으나 사용 중 데스크톱 패널 크기도 변경되었다. 모든 중간 프레임의 화면 크기가 고정되었다고 주장하지 않는다. 모든 구슬 수/화면 비율 조합과 모든 수동 제스처를 각각 재실행하지는 않았다. 기존 컨트롤·lifecycle 테스트가 해당 경계를 검증한다.

물리 변경 부재는 코드 경계와 기존 반복 seed 물리 회귀로 검증했다. 별도의 camera-on/off 물리 리플레이 비교는 추가하지 않았다. 배포 성공은 커밋·푸시와 별도로 확인해야 한다.
